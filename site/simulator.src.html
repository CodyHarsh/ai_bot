Pip, the talking AI bot

ESP32 with a microphone, speaker and a cute OLED face. You talk, an LLM answers out loud, and the face shows how Pip feels.

Built from your Cirkit settings. INMP441 mic, MAX98357A amp + speaker and the I2C OLED on SCK=GPIO19 / SDA=GPIO21, with the I2S clock on GPIO14 and GPIO25, mic data on GPIO33 and amp data on GPIO22. Your saved sketch only drew the face. The firmware here also records, talks to the server and plays the reply.

Serial monitor (115200)

Pressing Talk plays the whole path: the mic hears you, the ESP32 streams audio to the server, the server turns speech into text, asks the LLM, turns the answer into a voice, and the ESP32 plays it while the mouth moves. Replies in this simulator come from a small built-in rule set so it works offline.

16 emotions

Every face has glossy eyes, rosy cheeks or a small sparkle, and a gentle bob and blink. The LLM picks one with each reply. You can step through them in the real firmware with the serial commands n and p.

How the AI works

    
An ESP32 cannot run speech recognition or a language model, and it does not need to. It records your voice, a small Python server on your laptop does the thinking, and the ESP32 plays the answer. No API key is stored on the device.

    

      
flowchart LR
  M[INMP441 mic] --> E[ESP32
voice detection]
  E -->|WiFi: raw audio| S1[Server: Whisper
speech to text]
  S1 --> L[Claude
emotion + reply]
  L --> T[edge-tts
cute voice]
  T -->|WiFi: raw audio| E2[ESP32 playback]
  E2 --> A[MAX98357A + speaker]
  E2 --> O[OLED emotion face]
      

    

    

      

        
What each piece does

        
    
          
  • Voice detection (ESP32): it listens for sound above the room's noise, records until you pause, and streams the audio as it goes, so no big memory buffer is needed.
    • 
          
  • Speech to text: faster-whisper runs on the laptop CPU. Use tiny.en for speed, small.en for accuracy.
    • 
          
  • LLM: Claude Haiku answers in a fixed JSON shape: an emotion and 1 to 2 short sentences.
    • 
          
  • Text to speech: edge-tts with the child-like en-US-AnaNeural voice, converted to 16 kHz audio by ffmpeg.
    • 
          
  • Playback: the ESP32 streams the reply into the amplifier while the mouth moves with the loudness.
    • 
        

      

      

        
Modes

        
    
          
  • Buddy: cheerful chat and fun facts.
    • 
          
  • Study: calm coach, one practical tip.
    • 
          
  • Mood: empathetic pet that reacts to feelings.
    • 
          
  • Sleep: soft bedtime talk.
    • 
        

        
Switch by saying "study mode" (or buddy, mood, sleep), from the server page at http://localhost:8000, or with the serial keys 1 to 4.

      

    

    

      
Pip reads your tone and shows it on its face

      
Before answering, the server judges how you sound. The LLM does this, and a quick keyword check backs it up, so it works even when no LLM is reachable. Pip then shows a face that matches your feeling. If the LLM picks a cheerful face for someone who is hurting, the server corrects it.

      

        
You soundExamplePip's face

        
          
sad or lonely"I had a rough day"sad (cry if very upset)

          
angry"My brother is so annoying"pout

          
anxious"I am worried about my exam"shy

          
tired"I am so tired"sleepy

          
excited"I got the job!"excited

          
loving"I love you Pip"love

          
playful"Tell me a joke"silly

          
curious"What is the moon?"curious

        
      

      
All 15 faces are used. The model is told to use the whole range. If it just says "happy", the server picks a more specific face from what was said (a greeting gets a wink, a joke gets silly, a fun fact gets surprised, a thank you gets love, a goodnight gets sleepy), and it avoids showing the same cheerful face twice in a row. It understands simple negation: "I am not sad" is not treated as sad. The server prints the tone for each message, and sends it to the ESP32 in the X-Tone header.

    

    

      
Reply format the LLM must follow

      
{"tone": "sad|lonely|angry|anxious|tired|excited|loving|playful|happy|curious|neutral",
 "emotion": "happy|excited|love|wink|joy|silly|sleepy|sad|cry|pout|surprised|thinking|shy|starry|curious",
 "text": "1 or 2 short sentences, under 160 characters"}

      
The server sends the text as speech and the emotion name in the X-Emotion header, and the ESP32 draws that face.

    

    

      
The brain chain: Groq first, then ChatGPT, then Gemini

      
The server tries each brain in order. If one fails (no key, rate limit, no internet, no credit), the next one answers. A failed brain is skipped for 90 seconds so replies stay fast. If every brain fails, Pip uses built-in replies and keeps talking.

      
flowchart LR
  A[Groq
main, free] -->|fails| B[OpenAI
ChatGPT] -->|fails| C[Gemini
free] -->|fails| E[Built-in replies]
      

      

        
BrainGet itSet in the terminal or .env

        
          
Groq (main)Free key at console.groq.comGROQ_API_KEY=...

          
OpenAI (ChatGPT)Key at platform.openai.com, needs creditOPENAI_API_KEY=...

          
GeminiFree key at aistudio.google.comGEMINI_API_KEY=...

        
      

      
Set only the keys you have. A brain with no key is skipped. The terminal prints the chain when the server starts, and each reply shows which brain answered. The voice is always the same (the cute edge-tts voice), whichever brain wrote the reply. Keep keys in a .env file: copy .env.example to .env in the server folder and fill it in. It is ignored by git.

      
Want more brains? Add them to the order, for example export LLM_CHAIN=groq,openai,gemini,ollama,anthropic. Google may use free-tier Gemini prompts to improve its models, so keep private things out of it.
